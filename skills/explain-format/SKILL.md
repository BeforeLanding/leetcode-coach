# 解法拆解格式

材料来自 `taolu explain context <题号> --json`（`problem`、`solutions`、`cards`、`next_candidates`、`existing_note`）。**只用这份材料，不凭记忆补充题面或题解。** 讲解紧扣用户缓存的那份解法，不要换成另一种解法；如果你觉得有更好的做法，最多在最后一行提一句，不展开。

## 输出结构（顺序和标题固定，7 段一段不少）

### 1. 套路归属
只能写 `cards` 里已有的卡片（`名称（id）`，可以多张），或者明确写“**暂无对应卡片**”。不能编造卡名。
如果 `cards` 为空，但你觉得它属于 `taolu card list` 里的某张卡，写出来并**问用户**是否运行 `taolu card link`，不要自己执行。

### 2. 关键观察
**一句话**：为什么能这么做。

### 3. 怎么想到
从约束（数据范围、题目特征、要求的量）一步步推到这个套路的推理链，3–5 步，每步一句。这一段回答“灵神的代码很短，但怎么想到的”。

### 4. 与模板的差异
有关联卡时，对照 `cards[].template`：指出本题解法相对模板**改了哪几行、为什么改**。没有关联卡或卡里没有 `template`，写“无模板可对照”。

### 5. 易错点
边界、初始化、溢出、开闭区间、下标与值的混淆等，只写这份解法里真会踩的，每条一句。

### 6. Python 版
- 原解不是 Python：改写成等价的 Python，保持与原解相同的思路，不要换算法。
- 原解本来就是 Python：原样放出，逐行加中文注释。
- 写明时间复杂度和空间复杂度。
- 给一个自测：**让用户提供题目的示例输入输出**（题面不在仓库里，不要凭记忆编示例），然后手工跑一遍或写出可运行的小测试。用户还没给示例就在这里请他提供。

### 7. 同套路下一题
只能从 `next_candidates` 里选 1–2 道（写题号、标题、难度）。`next_candidates` 为空就写“这张卡的练习题已全部 AC”。不要推荐列表之外的题。

## 约束

- 用中文，段落短。代码块用 ```python。
- 题解正文是用户的本地学习材料：不要大段逐字复述原解的文字讲解，用自己的话讲“为什么”。
- 写完后由 `/taolu:explain` 命令负责 `explain save`，不要在这里自行存别的位置。
